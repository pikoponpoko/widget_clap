# 応援ウィジェット：統合仕様と実装の照合

2026-10-25。要求の優先順位は「今回の統合仕様 → 追加指示 → 当初計画書」。当初計画書は `creator_support_widget_plan_v2.md`、追加指示は会話中のPhase 1依頼と「まずWorkersでデプロイ可能な初期ブラウザ版、DB・決済は後続」の指示を参照する。

## 認識の修正

サービスの中心は、Web拍手のように**任意のWebページに貼れる小さな画像ボタン**。紹介ページや常設の大きな感想フォームを中心にしない。

- A: `/button/:slug` と `/embed.js`。ボタンの表示だけでは拍手を増やさない。押した時点で保存を行い、成功後にお礼画面を開く。
- お礼画面 `/widget/:slug`。拍手後にイラストを表示し、その後に任意メッセージ。感想を書かずに閉じても拍手は残る。
- B: `/admin`。既存の作者向け機能を継続する。公開中のブラウザ体験版はローカルの動作見本であり、本番の作者認証・受信とは区別する。
- C: `/about`。既存紹介ページを残す。優先度は低い。
- `/` と `/demo` は、配布ツール・作品・ブログへの**実際の埋め込みデモ**。別途作り直したサービス紹介ページではない。

## 合理的な仮仕様

1. 1つのslugを1設置先として扱う。同一作品の別ページを別集計したい場合は別slugにする。将来work_idとwidget_idを分離しても既存slugを維持する。
2. ボタンは標準128×52px。画像は120×44px内へ縦横比を維持して収める。アニメーションは画像本来の再生を使う。
3. 標準埋め込みは1行の外部script。scriptは自分のホスト要素内だけにDOMを追加し、Shadow DOMとiframeで隔離。ホストページのbodyや既存CSSは変更しない。
4. メッセージはお礼画面内の任意欄。感想ゼロでも拍手が成立する。初期表示、iframeロード、ダイアログの描画・再描画、画像表示では加算しない。
5. `/widget?after=clap` は拍手済み画面の表示指定であり、APIや件数の更新を行わない。クエリの指定だけでDBに拍手を追加することはできない。
6. 未接続の「投げ銭のみ」設定には、有効な支援ボタンを表示しない。設定は保存可能だが、公開には確認済みURLとサーバー許可が必要。支援金額は150/300/500円を後続設計で維持する。
7. 公開体験版の埋め込みはHTTP/HTTPSのサイトに許可。本番Owner版では登録オリジンだけをCSPで許可する。ホストサイト独自のCSPには配信元のscript-src/frame-src許可が必要。
8. ブラウザ体験版の保存はトップレベルサイトによって分離・制限されることがある。第三者サイトから作者へ実際に届ける機能は、サーバー接続後の検証対象。体験版を本番受信サービスとは表示しない。
9. dialog非対応ブラウザとscriptを使わない単純iframe向けには、お礼画面を別タブで開くリンクを用意する。標準script方式はボタン1回でダイアログを開く。

## 段階的な実装計画

1. **今回**：埋め込み小型ボタン、押下時の拍手、お礼、任意感想、実埋め込みデモ、配置・モバイル・メッセージ通信の検証。
2. 管理画面・画像・設置先設定・お気に入りを本番接続。お気に入り件数の定義と匿名での集計、実サイトのテーマA/B/C、Safari/iOS・アニメ互換性、D1/R2/Access/Turnstile、バックアップ復旧試験。
3. 既存の返信・CSV/JSON/PDF・印刷コードを本番データへ接続。返信リンクの認可を実環境で検証し、実際のシール用紙に100%印刷して91×55mmを実測。
4. カード決済を先行して外部支援リンクを検証。適法性・事業者許可・明細/領収書/法定表示の個人情報・返金/税務を確認。PayPayは審査・規約確認後に判断し、個人間送金は代用しない。
5. 一般公開、Free/Pro/Ownerのサーバー権限、課金、退会・基本データ取得/削除手段。Freeにも適切な取得・削除手段を残す。広告はさらに後で検討する。

今回、本番DB作成・決済契約・課金は行わない。先行したOwner版コードも削除・簡略化しない。
